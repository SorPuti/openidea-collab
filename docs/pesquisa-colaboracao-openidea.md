# Pesquisa: colaboração em tempo real no OpenIDEA

Data: 9 de novembro de 2026. Projeto analisado: commit local `8f6a0469f2c080f1ed2c1f1d225595688f4b3d65`; SDK do projeto: OpenIDEA v0.1.40, commit `37c2a6048eea89d4f6db645622612358b643862b` (API 1.4). O upstream `main` consultado estava em `bc048e241383e6c5ac8214904c1f9554cbf98d5f` (API 1.5 em desenvolvimento). API de plugins é preview. As conclusões abaixo separam código lido de comportamento testado; não houve teste com duas instâncias da IDE.

## Conclusão

O protótipo atual é sincronização de arquivos ao salvar, não edição simultânea por caractere. Para implementar colaboração nativa por digitação, o contrato público consultado não oferece eventos de alteração do documento em memória nem uma forma geral de aplicar edições a qualquer documento aberto não focado. Uma proposta de API no repositório principal parece necessária para atingir esse objetivo pela API pública; aceitação depende dos mantenedores. WebSocket nativo é uma possibilidade, não um requisito obrigatório: transporte e modelo de edição são problemas separados, e um processo auxiliar é uma alternativa sujeita a permissões e aos mesmos limites de integração do editor.

## Provas no projeto

1. `openidea-collab/plugin.toml` declara `project.read`, `project.write`, `events`, `storage`, `editor.read`, mas nenhuma capacidade `net:`. Todas as chamadas em `src/client.rs` usam `host::fetch`: em um host que aplique o contrato, a versão 0.2.0 não tem autorização declarada para acessar nem localhost. O comando de mudar URL não concede permissão. A política de host e eventuais regras para concessão dinâmica devem ser verificadas antes de escolher URLs arbitrárias.
2. `src/lib.rs:290` envia em `FileSaved`, comunica presença em `EditorFocused`, e recebe eventos apenas em `Scheduled`. O manifest usa `on-schedule:60`; a [documentação v0.1.40](https://github.com/l0ng-ai/openidea/blob/37c2a6048eea89d4f6db645622612358b643862b/plugins/README.md#activation) fixa 60 segundos como mínimo. O endpoint espera cinco segundos e **não acorda ao chegar evento**: dorme e consulta ao final (`collab-server/src/routes.rs:319`). A promessa de ~500 ms não está demonstrada.
3. `src/sync.rs:191` aplica o arquivo remoto com `project.write_file` e ignora falhas. A [documentação de capacidades](https://github.com/l0ng-ai/openidea/blob/37c2a6048eea89d4f6db645622612358b643862b/plugins/README.md#capabilities) informa que essa escrita é recusada quando o editor possui alterações não salvas. Logo não equivale a editar o buffer em memória, e a falha pode ficar invisível. Ainda é necessário validar o contexto de projeto nas invocações agendadas em execução real.
4. `collab-server/src/routes.rs:215` retorna HTTP 409 em divergência de versão entre usuários; não invoca `merge3`. `collab-server/src/document.rs` contém `merge3`, mas está marcado como código não usado. O README e a descrição do PR anunciam merge 3-way que o fluxo não executa. O aviso ao usuário recomenda salvar de novo, mas o cliente não ajusta a versão no 409: a recomendação não demonstra recuperação.
5. Presença usa apenas foco e atualização de arquivo, sem heartbeat periódico. Servidor remove membros após 30 segundos de inatividade (`room.rs:74`), com limpeza a cada 30 segundos (`main.rs:16`); cursor é obtido na troca de foco, não a cada movimento. A lista pode ficar desatualizada e participantes inativos podem expirar.
6. Servidor escuta em `0.0.0.0:4444` por padrão e os handlers não autenticam acesso à sala ou operações; `update_file` aceita `user_id` fornecido pelo cliente sem verificar membro. Qualquer pessoa que alcance o servidor e conheça a sala pode ler/alterar conteúdo e identidade. O estado está somente em memória. Não expor esse protótipo a rede pública antes de autenticação, autorização e proteção de transporte adequadas.
7. A tela tenta carregar imagens externas GitHub (`src/lib.rs`), mas a [CSP do host v0.1.40](https://github.com/l0ng-ai/openidea/blob/37c2a6048eea89d4f6db645622612358b643862b/src-tauri/src/plugin_web.rs) restringe `img-src` a recursos do plugin, data e blob. Isso indica que avatares externos provavelmente não carregarão; não foi verificado visualmente.

## Contrato oficial e desenho possível

- [WIT de eventos na versão usada](https://github.com/l0ng-ai/openidea/blob/37c2a6048eea89d4f6db645622612358b643862b/wit/events.wit) inclui arquivos salvos e foco, mas não mudança de buffer por edição nem movimento geral de cursor. `files-changed` acompanha filesystem, não mudanças não salvas. Eventos são agrupados e uma instância ociosa pode ser recolhida; consultar [eventos](https://github.com/l0ng-ai/openidea/blob/37c2a6048eea89d4f6db645622612358b643862b/plugins/README.md#events).
- [WIT de workspace](https://github.com/l0ng-ai/openidea/blob/37c2a6048eea89d4f6db645622612358b643862b/wit/workspace.wit) expõe leitura de documento e `apply-edits` com versão, usando `editor.read`/`editor.write`; `Invocation.editor` se refere ao editor focado. É útil, mas não demonstra assinatura contínua de mudanças nem escrita direcionada em todos os buffers abertos.
- [WIT de IO](https://github.com/l0ng-ai/openidea/blob/37c2a6048eea89d4f6db645622612358b643862b/wit/io.wit) expõe requisições HTTP, não uma API pública de WebSocket persistente. HTTPS exige `net:<host>`; HTTP remoto exige `net.http:<host>` desde API 1.4, enquanto HTTP loopback usa `net:<host>` (confira host exato e redirects). Não usar `net:*` como pressuposto. O contrato restringe resposta a 8 MiB. IPC local é Unix socket/named pipe, com `ipc:<path>`, não TCP; executar processo exige `process:<program>` e aprovação. Consultar [rede, limites e permissões](https://github.com/l0ng-ai/openidea/blob/37c2a6048eea89d4f6db645622612358b643862b/plugins/README.md#network-and-secrets).
- Para evolução, propor primeiro ao upstream eventos de documento aberto/alterado/fechado com identidade estável, versão, mudanças incrementais e origem, e aplicação de alterações remotas versionadas no documento correto, inclusive quando não focado. Especificar transações, undo, UTF-16, múltiplas janelas, evitar eco de mudanças remotas e testes. O formato exato precisa de discussão com mantenedores; não há garantia de aprovação.
- Escolher CRDT (por exemplo Yjs/Yrs) ou OT para concorrência, persistência/reconexão e snapshots, com protocolo versionado, identidade/autorização, limite de recursos e proteção de transporte. Nenhum desses recursos é fornecido automaticamente por HTTP ou WebSocket. Para um MVP intermediário, corrigir sync ao salvar e informar claramente limites e conflitos antes de alegar colaboração realtime.

## Publicação e PRs

[Registro oficial](https://github.com/l0ng-ai/openidea-plugins#publishing-a-plugin): pacote assinado Ed25519 e anexado a release, SHA-256, publisher com chave pública e owners, entrada do plugin, código público licenciado e justificativa de capacidades de maior risco. Novos publishers/plugins passam por revisão e merge; novas versões também entram por PR. Não é necessário ser aceito no marketplace para desenvolvimento local (`openidea-plugin link`); isso não remove o controle de permissões do host. Mudanças de WIT, SDK e host são propostas em PR separado no [repositório principal](https://github.com/l0ng-ai/openidea).
