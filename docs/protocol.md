# Protocol v1

## Control plane

Canonical production origin: `https://collab.synthosia.com`. WSS URL: `wss://collab.synthosia.com/v1/socket`. The operator can configure another secure public origin; plaintext is allowed only for loopback development. The plugin distribution is deliberately bound to the Synthosia origin.

| Method | Route | Authorization |
| --- | --- | --- |
| GET | `/healthz` | Public; no session data |
| GET | `/v1/info` | Public; protocol, transport and limits |
| POST | `/v1/sessions` | Public bootstrap with global rate/session caps; additional admission controls required for an untrusted public service |
| POST | `/v1/sessions/{id}/invitations` | Owner of that session |
| POST | `/v1/invitations/redeem` | Valid, unexpired, single-use secret; atomically consumed |
| POST | `/v1/sessions/{id}/documents` | Owner; registers an opaque document UUID |
| DELETE | `/v1/sessions/{id}/members/{member}` | Owner, or the member leaving itself |
| GET | `/v1/socket` | Bearer header, required subprotocol, native client |

Creation body: `{"protocol":1}`. Invitation body: `{"role":"editor","ttl_seconds":300}`; `viewer` is also supported, never `owner`. TTL must be 30–600 seconds. Session credentials expire with the session (four hours). UUIDs are public locators, not authentication. Credentials have 256 random bits and are stored as SHA-256 digests in authorization metadata.

Invitations use `https://collab.synthosia.com/join/<uuid>#<one-time-secret>`. The fragment is exchanged in a POST body; it is never a query parameter. The landing page has no third-party assets, uses `no-store`/`no-referrer` and clears the fragment from the current browser history entry. Clipboard and external sharing remain sensitive.

No endpoint accepts a user-supplied identity as proof of membership. Revocation is committed before idle sockets are signalled to close. Requests containing unknown fields are refused by the typed control schema.

## WebSocket transport

TLS is terminated by the reverse proxy. The application binds only to loopback. The handshake requires:

```text
Authorization: Bearer <individual credential>
Sec-WebSocket-Protocol: openidea-collab.v1
```

Query strings and browser Origin headers are refused. Credentials do not go into URLs or WebSocket subprotocol values. No permessage-deflate is enabled. The plugin reaches the v1 endpoint through the project-bound native host transport released in OpenIDEA v0.1.43, never through a sandboxed webview socket.

Client binary frame, big-endian integers:

| Offset | Bytes | Meaning |
| --- | --- | --- |
| 0 | 4 | `OIC1` |
| 4 | 1 | Kind: state vector=1, update=2, peer ACK=3, presence=4, snapshot=5 |
| 5 | 16 | Document UUID |
| 21 | 16 | Recipient UUID; nil means room broadcast |
| 37 | 16 | Message UUID |
| 53 | 2 | Chunk index |
| 55 | 2 | Chunk count |
| 57 | 4 | Total reassembled bytes |
| 61 | remaining | Opaque bytes |

The relay prefixes **16 bytes of authenticated sender UUID** on delivery. The recipient must allow the 16-byte envelope in addition to the 64 KiB inbound frame cap. It never trusts an identity supplied in payload. The document must already be registered in the authenticated session; targeted recipients must belong to that session.

Only owners/editors can send updates/snapshots. Readers may request state, acknowledge or send bounded presence. Presence and state-vector/ACK control frames are not chunked. ACK contains the acknowledged message UUID, requires a recipient and is not generated by the relay. Its durability meaning belongs to the receiving client's persistence contract; the transport itself guarantees no persisted document state.

Reassembly is a client operation: up to four in-flight transfers, 64 chunks, 2 MiB per transfer and 30-second expiry. Duplicate identical chunks are harmless; inconsistent duplicates or envelope changes are refused. Empty/unknown/oversized/malformed frames close the sending connection. Large transfers use bounded application chunks, not an unbounded WebSocket message.

## Resource defaults

- Sixteen sessions, three members per session, sixty-four sockets globally. HTTP handling is capped at 32 in-flight requests and five seconds per request. Metadata writes are serialized on one blocking operation.
- Sixty-four registered document IDs per session; sixteen live invitations.
- Four queued messages per recipient; 64 KiB per client message plus sender envelope on output.
- Input token buckets: 60 frames/s with burst 120; 256 KiB/s with burst 512 KiB.
- Presence: 5/s, burst 5. Excess presence is dropped; excessive document traffic closes the sender.
- Socket write timeout: five seconds; heartbeat/expiry check every fifteen seconds.
- Session creation: global burst four, refill one per thirty seconds. An internet deployment needs operator admission/antiabuse beyond this small-instance cap.

The relay does not retain a replay backlog. Clients reconnect using Yrs state vectors and an authorized peer with the document. No fallback, HTTP document polling, offline cloud copy or E2EE is claimed.
