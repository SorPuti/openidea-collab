# Evidências: registro OpenIDEA Plugins — 10/11/2026

Escopo: leitura do código público e das regras, sem modificar upstream ou executar builds. Referência fixada no commit [`b958f4c3fa3fe2da523cf5911e4ce986644802e9`](https://github.com/l0ng-ai/openidea-plugins/tree/b958f4c3fa3fe2da523cf5911e4ce986644802e9). Estas são evidências de implementação/documentação; não substituem execução do CI nem aceitação do mantenedor.

## O que o registro efetivamente exige

1. A entrada de publisher associa prefixo, proprietários GitHub e chave pública Ed25519; o plugin tem ID `<publisher>.<nome>`. Cada versão do pacote é vinculada a URL e SHA-256 e assinada com a chave do publisher. O repositório declara que o CI faz download, verifica hash, executa `openidea-plugin check` e verifica assinatura antes de produzir o índice ([README 15–27](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/README.md#L15-L27)). O repositório fonte do plugin deve ser público e ter licença open source; o pacote deve ser construído a partir dele. README do plugin deve explicar a funcionalidade e cada capability de alto risco. Código ofuscado/minificado fora do código-fonte é proibido ([README 79–93](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/README.md#L79-L93)). Assinatura e hash não comprovam por si só origem reproduzível, autorização, segurança ou integridade do código em execução.
2. `publishers/<id>.toml` aceita apenas `name`, `owners`, `keys`, `revoked-keys` e `endorsements`. O parser valida owners e chaves Ed25519 em base64; chaves listadas e revogadas não podem coincidir ([registry.py 104–125](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/scripts/registry.py#L104-L125)). O validador rejeita chaves desconhecidas na entrada do plugin; apenas `repository` e `versions` no topo e `version`, `package`, `sha256` por versão são aceitas; URLs exigem prefixo HTTPS; ID, versão e hash são validados ([registry.py 155–185](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/scripts/registry.py#L155-L185)). Portanto `description` no TOML de registro não é aceito: descrever funcionalidade no README, manifesto do pacote e PR conforme respectivos schemas.
3. O CI roda testes, valida PR usando script da branch **base** e proprietários anteriores à alteração, obtém `openidea-plugin` da versão mais recente do OpenIDEA (fallback compilado de main), busca pacotes, executa check e gera índice ([workflow 29–74](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/.github/workflows/registry.yml#L29-L74)). Novos publishers/plugins exigem revisão de mantenedor; atualizações pelo owner exigem checks e merge ([README 79–85](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/README.md#L79-L85)). A descrição do PR deve identificar plugin/origem, mudanças/capabilities, pacote assinado e check ([template 1–8](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/.github/pull_request_template.md#L1-L8)).
4. A documentação pede nova tabela `[[versions]]`, mantendo versões anteriores que atendem requisitos de API diferentes; OpenIDEA escolhe a mais recente compatível e o índice preserva a mais recente por requisito, podendo remover tabelas que já não sejam necessárias ([README 70–77](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/README.md#L70-L77)). **Não confundir recomendação com enforcement**: no trecho revisado, a rotina compara os conjuntos de versões para gerar notas e aceita “details changed”; não há comparação de hash/URL anterior impondo imutabilidade ([registry.py 281–291](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/scripts/registry.py#L281-L291)). Preservar tags/releases e publicar nova versão é medida de procedência do projeto e do caso sob revisão; não alegar que essa rotina garante imutabilidade.
5. A busca tenta espelho primeiro, recorre à URL do autor se faltante ou hash divergente, e só grava pacote cujo hash corresponde; o limite de download do registro é 256 MiB ([registry.py 34–39](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/scripts/registry.py#L34-L39), [371–395](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/scripts/registry.py#L371-L395)). Isso não demonstra que auxiliares nativos sejam permitidos no pacote ou executáveis via permissão da IDE: conferir separadamente o host/manifesto.
6. Rotação deve manter chave anterior e endosso da nova quando possível; o processo de revogação é dos mantenedores ([README 99–121](https://github.com/l0ng-ai/openidea-plugins/blob/b958f4c3fa3fe2da523cf5911e4ce986644802e9/README.md#L99-L121)). Não incluir chave privada nos repositórios ou relatórios.

## Aplicação ao PR #102

O [comentário do mantenedor](https://github.com/l0ng-ai/openidea-plugins/pull/102#issuecomment-6756170352) informa que checksum, assinatura e `openidea-plugin check` **do pacote revisado v0.1.0** passaram, mas recusa a listagem por garantias de escrita, isolamento de projeto, segredos, autenticação, integridade, funcionamento e divergências entre tag/fonte/pacote. Passar novamente os checks é necessário, mas não é comprovação das correções. Fornecer testes por requisito, publicar nova tag e pacote da fonte correspondente, conferir ID/versão/licença/assinatura/hash, adicionar URL/SHA ao PR e aguardar revisão/merge humano. O pacote preview.3 não assinado e vinculado como desenvolvimento não deve ser apresentado como pacote de marketplace.

A licença Apache-2.0 deste repositório de registro é distinta da licença do repositório Collab; esta leitura não conclui automaticamente quais obrigações de terceiros se aplicam ao pacote Collab. Conferir licenças efetivamente distribuídas e avisos antes da release.
